# Задача: практическая WebGL-симуляция NovaLab «Лаборатория задач: закон Архимеда»

## Контекст

Ты работаешь в Unity-проекте платформы **NovaLab** (интерактивные уроки физики; в коде Unity-проекта папки и
пространства имён называются `PhysLab` — сохраняем для совместимости). Подключён к редактору через Unity MCP.
Каждая симуляция — отдельная сцена и отдельный WebGL-билд, встраиваемый сайтом через `<iframe>`.

Это **практический модуль**: ученик **сам составляет условие задачи** на архимедову силу, **решает её**,
**вводит ответ**, получает проверку и разбор, а результат уходит **учителю в статистику**.
Тема — 7 класс, Перышкин § 50–53: F_A = ρ_ж·g·V, вес тела в жидкости P₁ = P − F_A, условие плавания.

Сайт уже умеет такую практику в простом веб-виде. Твоя задача — **наглядная лабораторная** Unity-версия,
которая общается с сайтом **точно в том же формате задачи**: сервер повторно решает задачу ученика и только
потом пишет результат в статистику. Эталонная логика (прочитай обязательно):

- `C:\Users\Asus\Desktop\FizLabProject\physlab\lib\practice\common.ts` — допуск проверки, форматирование
- `C:\Users\Asus\Desktop\FizLabProject\physlab\lib\practice\archimedes.ts` — жидкости, единицы, тексты условий,
  валидация (в т. ч. «тело всплывёт», «кораблик утонет пустым»), решение

## Контракт с сайтом

- `ModuleRoot.Init(json)` получает `{ "topic": "archimedes", "goal": 3 }`. Пустой/битый конфиг → дефолты.
- После **каждой проверки ответа** — `PhyslabPost`:
  ```json
  { "type": "taskResult",
    "data": { "topic": "archimedes",
              "task": { "unknown": "FA", "g": 9.8, "liquid": "water",
                        "V": { "value": 200, "unit": "cm3" }, "answerUnit": "N" },
              "answer": 1.96,
              "solutionText": "необязательно" } }
  ```
- **Формат задачи (не менять — его проверяет сервер):**

  | unknown | что найти | нужные поля | answerUnit |
  |---|---|---|---|
  | `FA` | архимедову силу | `liquid`, `V` | `N`, `kN` |
  | `V` | объём тела | `liquid`, `FA` | `cm3`, `dm3`, `m3` |
  | `rho` | плотность жидкости | `V`, `FA` (без `liquid`) | `kg/m3`, `g/cm3` |
  | `P1` | вес тела в жидкости | `liquid`, `P`, `V` | `N`, `kN` |
  | `cargo` | наибольший груз кораблика | `liquid`, `L`, `W`, `H` (см), `hullMass` (кг) | `kg`, `g` |

  - Во всех задачах `g`: строго `9.8` или `10`.
  - `liquid`: `water` 1000, `saltwater` 1030, `oil` 930, `kerosene` 800, `alcohol` 800, `mercury` 13600 (кг/м³).
  - `V.unit`: `cm3`, `dm3`, `m3`; `FA.unit` и `P.unit`: `N`, `kN`.
  - Все значения > 0. `P1`: если F_A ≥ P, это ошибка («тело всплывёт»). `cargo`: если ρ·L·W·H ≤ hullMass —
    ошибка («утонет пустым»).
- Правильность: |ответ − верное| ≤ max(1,5 % от верного; 0,01). C#-порт обязан давать тот же результат, что `archimedes.ts`.
- Текст условия — по шаблонам `describe()` из `archimedes.ts` (те же падежи: «в керосин», «в морской воде»).

## Как ученик составляет задачу — лабораторный стол

Сцена — лабораторный стол: аквариум с жидкостью, штатив с динамометром, набор тел, отливной сосуд с мерным
стаканом, кораблик. Ученик **собирает опыт**, и из него получается условие.

1. **Что найти** — пять карточек (F_A, V, ρ, P₁, груз). Искомая величина в сцене закрыта табличкой «?»:
   показания динамометра или мерного стакана скрыты, на сосуде с неизвестной жидкостью написано «?».
2. **Жидкость** — канистры на полке, выбранная «наливается» в аквариум (цвет и вязкость немного разные).
   Для `rho` жидкость «секретная»: ученик задаёт V и F_A, а какая это жидкость, станет ясно после проверки.
3. **Тело** — ползунок размера тела показывает объём и пересчитывает его в выбранные единицы (см³/дм³/м³).
   Вес P задаётся гирькой-грузиком на теле или полем ввода.
4. **F_A** (когда это дано) — задаётся «показанием» разности динамометров или полем ввода.
5. **Кораблик** — ручки-стрелки меняют L, W, H корпуса прямо на модели, масса — ползунком.
6. **g** — переключатель 9,8 / 10 Н/кг на доске.
7. Внизу в реальном времени собирается **текст задачи**. Ошибки валидации — красным, с подсказкой, как исправить
   (например, «Тело всплывёт: увеличьте вес»). Сложность ★–★★★ — как `difficulty()` в `archimedes.ts`.

## Решение и проверка

1. Экран «Реши»: условие крупно, поле «Решение» (необязательно, увидит учитель), поле ответа с единицами.
2. **«Проверить опытом»** — опыт проводится в сцене:
   - **FA / P1**: тело на динамометре плавно опускается в жидкость, стрелка динамометра падает до правильного
     значения; на шкале отмечено значение ученика — видно расхождение.
   - **V**: тело погружается, жидкость переливается в мерный стакан, уровень = правильный объём; отметка
     ученика на стакане.
   - **rho**: после опыта табличка «?» снимается, видна жидкость и её плотность из таблицы учебника
     (если такой нет — «жидкости с такой плотностью нет в таблице»).
   - **cargo**: в кораблик по одной кладутся гири; на массе, которую назвал ученик, ставится отметка, кораблик
     оседает и в момент перелива через борт тонет — видно, сколько груза он на самом деле выдерживал.
   Стрелки F_A и F_тяж с подписями во время опыта.
3. Вердикт и **разбор по шагам**, как `solve()` в `archimedes.ts`: данные → перевод в СИ → формула → подстановка →
   перевод в единицы ответа. Кнопки «Попробовать ещё раз» и «Составить новую задачу».
4. Каждая проверка → `taskResult`. Прогресс «2 из 3» по `goal`. Совет на экране: «Реши задачи разных типов».

## Тесты (EditMode) — те же эталоны, что на сайте

| Задача | Ответ |
|---|---|
| FA? вода, V = 0,002 м³, g = 9,8 | 19,6 Н |
| FA? керосин, V = 50 см³, g = 9,8 | 0,392 Н |
| V? вода, F_A = 5 кН, g = 10, ответ в м³ | 0,5 |
| rho? V = 500 см³, F_A = 4 Н, g = 10 | 800 кг/м³ (керосин или спирт) |
| P1? вода, P = 10 Н, V = 400 см³, g = 10 | 6 Н |
| cargo? вода, 40 × 20 × 10 см, кораблик 0,5 кг | 7,5 кг |
| cargo? керосин, те же размеры | 5,9 кг |

Плюс: P1 при P = 1 Н, V = 1 дм³ в воде → ошибка «всплывёт»; ответ 19 при верном 19,6 — неверно; 19,4 — верно;
текст первой задачи совпадает с `describe()` символ в символ.

## Сборка и подключение

- Меню PhysLab → Build WebGL → Archimedes Practice, выход `Builds/WebGL/archimedes-practice/`.
- Подключение к сайту (делает человек): `npm run unity:import -- "<папка билда>" archimedes-practice`.

## Проверка (Definition of Done)

1. Консоль без ошибок, тесты проходят.
2. Скриншоты: составление каждого из 5 типов задач; ошибка «тело всплывёт»; опыт для FA с отметкой ученика;
   раскрытие «секретной» жидкости для rho; кораблик тонет при перегрузе; разбор решения.
3. `SendMessage("ModuleRoot","Init","{\"topic\":\"archimedes\",\"goal\":5}")` → прогресс из 5 задач.
4. В логе редактора — `taskResult` строго по формату выше.
5. Отчёт: дерево файлов, что добавлено в Core/Practice, пример реального JSON `taskResult`.

Работай поэтапно: разведка → порт логики и тесты → лабораторный стол и составление условия → опыт-проверка →
UI → сборка.
