# Задача: практическая WebGL-симуляция NovaLab «Конструктор задач: движение»

## Контекст

Ты работаешь в Unity-проекте платформы **NovaLab** (интерактивные уроки физики; в коде Unity-проекта папки и
пространства имён называются `PhysLab` — сохраняем для совместимости). Подключён к редактору через Unity MCP.
Каждая симуляция — отдельная сцена и отдельный WebGL-билд, который сайт встраивает через `<iframe>`.

Это **практический модуль**: ученик **сам составляет условие задачи** на равномерное движение, **решает её**,
**вводит ответ**, получает проверку и разбор, а результат уходит **учителю в статистику**.
Тема — 7 класс, Перышкин § 16–17: v = s / t, s = v·t, t = s / v, 1 м/с = 3,6 км/ч.

Сайт уже умеет такую практику в простом веб-виде. Твоя задача — сделать **наглядную и увлекательную**
Unity-версию, которая общается с сайтом **точно в том же формате задачи**: сервер повторно решает задачу ученика
своей функцией и только после этого записывает результат в статистику. Эталонная логика (прочитай обязательно):

- `C:\Users\Asus\Desktop\FizLabProject\physlab\lib\practice\common.ts` — допуск проверки, форматирование
- `C:\Users\Asus\Desktop\FizLabProject\physlab\lib\practice\speed.ts` — объекты, единицы, тексты условий, валидация, решение

## Контракт с сайтом

- `ModuleRoot.Init(json)` получает `{ "topic": "speed", "goal": 3 }` (goal — сколько задач решить верно).
  Частичный/пустой конфиг → дефолты, битый JSON не роняет сцену.
- После **каждой проверки ответа** отправить через `PhyslabPost`:
  ```json
  { "type": "taskResult",
    "data": { "topic": "speed",
              "task": { "unknown": "s", "mover": "cyclist",
                        "v": { "value": 18, "unit": "km/h" },
                        "t": { "value": 20, "unit": "min" },
                        "answerUnit": "km" },
              "answer": 6,
              "solutionText": "необязательно: ход решения, который ученик записал" } }
  ```
- **Формат задачи (не менять — его проверяет сервер):**
  - `unknown`: `"s"` | `"v"` | `"t"` — что найти; передаются только две **другие** величины.
  - `mover`: `pedestrian`, `runner`, `cyclist`, `car`, `train`, `plane`, `snail`.
  - `s.unit`: `m`, `km`; `v.unit`: `m/s`, `km/h`; `t.unit`: `s`, `min`, `h`; значения > 0 и ≤ 10⁷.
  - `answerUnit`: из единиц искомой величины (для `s` — `m`/`km`, для `v` — `m/s`/`km/h`, для `t` — `s`/`min`/`h`).
  - `answer` — число в единицах `answerUnit`.
- Правильность: |ответ − верное| ≤ max(1,5 % от верного; 0,01). Сайт показывает тот же вердикт, что и Unity,
  поэтому C#-порт обязан давать **тот же** результат, что `speed.ts`.
- Текст условия в Unity строй по шаблонам из `describe()` в `speed.ts` (те же формы слов: «проедет», «проползла» и т. д.).

## Как ученик составляет задачу (это главное — сделай наглядно)

Сцена — та же трасса вид сбоку (2,5D). Составление условия — **через сцену, а не только через поля ввода**:

1. **Кто движется** — карусель персонажей над трассой (пешеход, бегун, велосипедист, автомобиль, поезд, самолёт,
   улитка), выбранный встаёт на старт.
2. **Что найти** — три большие карточки «Путь s», «Скорость v», «Время t». Искомая величина в сцене
   показывается знаком «?».
3. **Данные** — каждой величиной управляет свой объект в сцене (рядом дублируется точным полем ввода):
   - путь **s** — перетаскивание финишного флажка по трассе (шкала в м/км), колесо мыши — точная подстройка;
   - скорость **v** — крутилка-спидометр над персонажем (м/с или км/ч);
   - время **t** — циферблат секундомера, стрелку можно крутить (с, мин или ч).
   Единицы переключаются кнопками прямо на объекте; числа на трассе пересчитываются под масштаб.
4. **Единицы ответа** — переключатель у карточки искомой величины.
5. Внизу в реальном времени собирается **текст задачи** (как в учебнике). Подсказки валидации — мягкие
   («Улитка со скоростью 30 м/с? Похоже на ошибку, но решать можно»), ошибки — блокируют кнопку «Решать».
6. **Сложность** ★–★★★ считай как в `difficulty()` в `speed.ts` и показывай сразу — пусть ученик сам усложняет
   задачу переводом единиц.

## Решение и проверка

1. Экран «Реши»: условие крупно, сцена замирает. Поле «Решение» (необязательно, увидит учитель) и поле ответа
   с единицами. Калькулятор не нужен.
2. После ввода ответа — **«Проверить опытом»**: запуск движения в ускоренном времени.
   - Для **s**: на трассе ставится полупрозрачный флажок-«прогноз» в точке ответа ученика; персонаж едет t секунд
     и останавливается в правильной точке — видно, недолёт это или перелёт и на сколько метров.
   - Для **t**: секундомер идёт, на циферблате отмечено время ученика; когда персонаж пересекает финиш,
     видно, раньше или позже прогноза.
   - Для **v**: рядом едет «призрак» со скоростью ученика — они финишируют в разное время, если ответ неверен.
3. Вердикт: «Верно!» (конфетти, звезда в прогрессе) или «Пока неверно» + правильный ответ.
   **Разбор решения** по шагам, как `solve()` в `speed.ts`: перевод в СИ → формула → подстановка → перевод в
   единицы ответа. Кнопки «Попробовать ещё раз» (то же условие) и «Составить новую задачу».
4. Каждая проверка → событие `taskResult` (и при верном, и при неверном ответе). Прогресс «2 из 3» по `goal`.
5. Историю своих задач в этой сессии ученик видит в свёрнутом списке.

## UI, производительность, WebGL

- UI Toolkit, на русском, палитра NovaLab: `#01597B`, `#5DB3C1`, `#99D8DE`, `#E2E8ED`, `#F2BA00`; ошибки `#E0525B`.
- Кириллица (TMP font asset 0400–04FF или динамический шрифт), десятичная запятая и в выводе, и во вводе
  («2,5» и «2.5» принимаются).
- Тач: перетаскивание флажка и крутилки работают пальцем на интерактивной доске; элементы ≥ 32 px.
- 900×506 (iframe) … 1920×1080; 60 FPS на встроенной графике, без теней и постпроцессинга, пул объектов.
- Compression Format = Disabled (или сжатие + Decompression Fallback). Шаблон WebGL = `Physlab`.
- Не использовать System.Threading, файловую систему, `Application.OpenURL`.

## Тесты (EditMode) — те же эталоны, что на сайте

| Задача | Ответ |
|---|---|
| s? велосипедист, v = 18 км/ч, t = 20 мин, ответ в км | 6 |
| v? пешеход, s = 900 м, t = 10 мин, ответ в м/с | 1,5 |
| t? автомобиль, s = 144 км, v = 72 км/ч, ответ в ч | 2 |
| v? автомобиль, s = 144 км, t = 2 ч, ответ в м/с | 20 |

Плюс: ответ 5 вместо 6 — неверно; ответ 6,05 — верно (допуск 1,5 %); отрицательная скорость — ошибка валидации;
текст условия для первой задачи совпадает символ в символ:
«Велосипедист едет равномерно со скоростью 18 км/ч. Какой путь он проедет за 20 мин? Ответ дайте в км.»

## Сборка и подключение

- Меню PhysLab → Build WebGL → Speed Practice, выход `Builds/WebGL/speed-practice/`.
- Подключение к сайту (делает человек): `npm run unity:import -- "<папка билда>" speed-practice`.

## Проверка (Definition of Done)

1. Консоль без ошибок, тесты проходят.
2. Скриншоты: составление задачи (флажок, спидометр, секундомер, текст условия); экран «Реши»; «Проверить опытом»
   с флажком-прогнозом при неверном ответе; разбор решения; задача с улиткой и подсказкой о нереалистичности.
3. `SendMessage("ModuleRoot","Init","{\"topic\":\"speed\",\"goal\":2}")` → прогресс из 2 задач.
4. В логе (в редакторе — Debug.Log вместо PhyslabPost) видно событие `taskResult` с JSON строго по формату выше.
5. Отчёт: дерево файлов, что добавлено в Core/Practice, пример реального JSON `taskResult`.

Работай поэтапно: разведка → порт логики и тесты → составление условия → решение и проверка опытом → UI → сборка.
