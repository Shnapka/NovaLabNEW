## Контракт с сайтом (не менять)

1. WebGL-шаблон после `createUnityInstance` отправляет: `parent.postMessage({ source: "physlab-module", type: "ready" }, "*")`.
2. Сайт отвечает `{ source: "physlab-host", type: "init", config: {...} }`, шаблон вызывает
   `SendMessage("ModuleRoot", "Init", JSON.stringify(config))`.
3. Unity → сайт: через jslib `PhyslabPost(json)`, где `json = {"type":"...","data":{...}}`; jslib сам добавляет `source: "physlab-module"`.
4. Корневой объект сцены называется строго **`ModuleRoot`**.
5. `config` может прийти пустым или частичным: отсутствующие поля = значения по умолчанию
   (используй `JsonUtility.FromJsonOverwrite` поверх объекта с дефолтами), значения вне диапазона — клампить.
   Битый JSON не должен ронять симуляцию: лог + дефолты.
6. В редакторе (без сайта) симуляция сразу работает с конфигом по умолчанию.
7. Разрешённое расширение: сообщение `{ source: "physlab-host", type: "set", config: {...} }` → шаблон вызывает
   `SendMessage("ModuleRoot", "SetParams", json)` для смены параметров на лету.

## Этап 2. Симуляция «Закон Архимеда: кораблик»

### Педагогическая цель
Ученик видит, что выталкивающая сила равна весу вытесненной жидкости, что тело плавает, когда F_A = F_тяж,
и понимает, почему стальное судно плавает, а стальной брусок той же массы тонет.

### Сцена
- Аквариум с прозрачными стенками и шкалой высоты в сантиметрах.
- Жидкость: полупрозрачная поверхность с лёгкой волной (простой шейдер, без тяжёлых отражений); цвет зависит от жидкости.
- **Режим «Кораблик»**: баржа с **коробчатым корпусом** (так объём погружённой части точно равен L·W·d).
  Груз — стопка гирь в трюме, высота стопки зависит от массы груза.
- **Режим «Брусок»**: сплошной брусок выбранного материала и объёма — для сравнения с корабликом.
- Рядом **мерный стакан**: уровень = вытесненный объём, подпись «V = 1,50 л · m = 1,50 кг · P = 14,7 Н».

### Физика (`BuoyancyModel`, g = 9,8 Н/кг)
- Кораблик: S = L·W, m = hullMass + cargoMass, осадка y ∈ [0; H].
  V_погр = S·y, **F_A = ρ_ж·g·S·y**, F_тяж = m·g.
- Равновесная осадка **d\* = m / (ρ_ж·S)**. Если d\* ≤ H — плавает; запас плавучести = (H − d\*) / H.
- Если d\* > H — перегрузка: вода переливается через борт, кораблик тонет и ложится на дно. После затопления
  выталкивающая сила считается только по объёму материала корпуса (константа плотности материала корпуса,
  например 1200 кг/м³). Это упрощение явно опиши в README.
- Динамика по вертикали: m·a = F_A − F_тяж − k·v (k подобрать так, чтобы колебания затухали за 2–3 с),
  интегрирование в FixedUpdate полунеявным Эйлером. При смене параметров кораблик плавно оседает или всплывает
  к новому равновесию — это наглядно. **Не используй Rigidbody/встроенную физику для плавучести**: числа в HUD
  должны точно совпадать с формулами.
- Брусок: ρ_т < ρ_ж — плавает, погружённая доля = ρ_т / ρ_ж; ρ_т = ρ_ж — плавает внутри жидкости;
  ρ_т > ρ_ж — тонет, на дне показать F_A = ρ_ж·g·V < m·g и силу реакции дна.
- Тесты (EditMode), минимум:
  - 1,5 кг, 0,40 × 0,20 м, вода → d\* = 0,01875 м, F_A = 14,7 Н;
  - в воде кораблик 0,40 × 0,20 × 0,10 м тонет при общей массе > 8 кг, в керосине — > 6,4 кг;
  - дубовый брусок (700) в воде погружён на 70 %, железный тонет;
  - динамика сходится к d\* с погрешностью < 1 мм за 5 с моделируемого времени;
  - конфиг: пустой `{}` → дефолты, значения вне диапазона клампятся, битый JSON не бросает исключение.

### Наглядность
- Стрелки сил: F_тяж (вниз, коралловый `#E0525B`) из центра масс, F_A (вверх, `#5DB3C1`) из центра погружённого
  объёма; длина пропорциональна силе, подписи «F_A = 14,7 Н». В равновесии стрелки равной длины.
- Ватерлиния на корпусе + шкала осадки в сантиметрах.
- Погружённая часть подсвечена полупрозрачным объёмом «вытесненная жидкость».
- HUD с живой формулой и подстановкой чисел:
  `F_A = ρ_ж · g · V = 1000 · 9,8 · 0,0015 = 14,7 Н`, `F_тяж = m · g = 1,5 · 9,8 = 14,7 Н`,
  статус «Плавает ✓» / «Тонет ✗», «Запас плавучести 81 %».
- Раскрывающаяся подсказка «Почему?» с условием плавания тел.

### События на сайт (через `PhyslabPost`)
- `started` — после Init.
- `paramsChanged` `{ key, value }` — с дебаунсом 300 мс.
- `equilibrium` `{ mode, liquidDensity, totalMass, draft, displacedVolume, buoyancy, gravity, floats }` — когда тело успокоилось.
- `sank` `{ totalMass, maxBuoyancy }`.

### Производительность и WebGL
- 60 FPS на встроенной графике: без real-time теней (или одна направленная с низким разрешением),
  без постпроцессинга, лёгкий шейдер воды.
- Билд по возможности < 20 МБ; Managed Stripping Level — Medium; Compression Format — Disabled
  (или Brotli + Decompression Fallback: настроить заголовки сервера мы пока не можем).
- Не использовать System.Threading, файловую систему, `Application.OpenURL`.

### Сборка
- `PhysLabBuild`: меню PhysLab → Build WebGL → Archimedes Boat; шаблон `PROJECT:Physlab`, только сцена
  ArchimedesBoat, выход `Builds/WebGL/archimedes-boat/` (вне Assets). После сборки вывести путь.
- Полную сборку запусти один раз в конце для проверки.
