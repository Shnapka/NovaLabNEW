# Задача: WebGL-симуляция PhysLab «Скорость, путь и время: гонка на трассе»

## Контекст

Ты работаешь в Unity-проекте PhysLab и подключён к редактору через Unity MCP. Проект — набор WebGL-симуляций для
школьной платформы PhysLab: каждая симуляция — отдельная сцена и отдельный WebGL-билд, который сайт встраивает
через `<iframe>`, передаёт ему настройки урока и получает события.

Аудитория — 7 класс, учебник А. В. Перышкина, § 16–17 «Скорость. Единицы скорости», «Расчёт пути и времени
движения». Формулы: **v = s / t, s = v·t, t = s / v**, 1 м/с = 3,6 км/ч, средняя скорость v_ср = (s₁ + s₂) / (t₁ + t₂).
Запуск — Chrome/Edge/Яндекс.Браузер на слабых школьных ноутбуках и интерактивной доске (мышь и тач).

**Главное требование: симуляция должна быть интересной.** Ученику должно хотеться нажать «Старт» ещё раз:
живые персонажи, понятная цель, мгновенная обратная связь, звёзды за точные прогнозы.

## Модель (RaceModel — чистый C#, без MonoBehaviour)

- Положение задаётся **аналитически**, а не накоплением: s_i(t) = min(v_i · t, distance), t_finish_i = distance / v_i
  (v = 0 → никогда не финиширует). Благодаря этому заезд можно перематывать по шкале времени в обе стороны
  без накопления ошибок, а числа на табло всегда точно совпадают с формулами.
- Режим «Средняя скорость»: кусочно-линейное s(t): участок 1 (avgS1 со скоростью avgV1), затем участок 2
  (avgS2 со скоростью avgV2); t₁ = s₁/v₁, t₂ = s₂/v₂, v_ср = (s₁ + s₂)/(t₁ + t₂).
- Время симуляции: t ∈ [0; t_max], где t_max = время финиша самого медленного участника, но не больше 600 с
  (иначе медленный пешеход на 500 м превратит урок в ожидание).
- Тесты (минимум):
  - v = 2 м/с, t = 10 с → s = 20 м; v = 5 м/с, distance = 100 м → t_finish = 20 с;
  - 72 км/ч ↔ 20 м/с;
  - средняя скорость: 60 м при 2 м/с + 40 м при 8 м/с → 35 с, v_ср ≈ 2,857 м/с (≠ 5);
  - перемотка: s(t) после «вперёд до 15 с → назад до 7 с» равно s(7);
  - v = 0 не даёт деления на ноль;
  - конфиг: `{}` → дефолты, значения вне диапазона клампятся, битый JSON не бросает исключение.

## Сцена и наглядность

- **Трасса вид сбоку (2,5D)**: стилизованная low-poly улица/стадион, разметка каждые 10 м с подписями,
  финишная арка, лёгкий параллакс фона (облака, деревья). Камера: «Вся трасса» (всё видно, числа читаются)
  или «Следить за лидером» (плавно, без укачивания); переключатель в UI.
- **Участники на своих дорожках (до 3)**: пешеход 1,4 м/с, бегун 6 м/с, велосипедист 5 м/с, автомобиль 17 м/с,
  гепард 30 м/с. Типичная скорость — значение по умолчанию при выборе персонажа, слайдер её меняет.
  Анимация шагов/колёс синхронизирована со скоростью (быстрее едет — быстрее крутятся колёса).
  Простые модели или стилизованные спрайты, но с характером. Подпись над каждым: «5 м/с · 37,5 м».
- **Метки-«следы»** через равные промежутки времени (trailInterval): флажки или следы ног/шин цвета участника.
  Ключевой визуальный вывод: у равномерного движения метки на равных расстояниях; у быстрого — дальше друг от друга.
- **Секундомер** крупно сверху, **табло** у каждого: скорость (м/с или км/ч), пройденный путь, время.
- **График s(t)** под трассой (LiveGraph), синхронный с трассой: линии цветов участников рисуются по ходу заезда,
  вертикальный курсор текущего момента. Переключатель s(t) / v(t); на v(t) путь закрашен прямоугольником
  («путь = площадь под графиком»).
- **Шкала времени (timeline)**: ползунок 0…t_max — перемотка заезда, кнопки ▶/⏸, «шаг 1 с», ⟲, скорость
  воспроизведения ×0,5 / ×1 / ×2 / ×5.
- **Финиш**: конфетти и пьедестал с временами, формула для победителя с подстановкой чисел:
  `t = s / v = 100 м / 5 м/с = 20 с`.
- Звук (короткие, отключаемые одной кнопкой): старт, финиш, звезда. По умолчанию звук выключен — это урок в классе.

## Режимы

1. **«Заезд»** — свободный эксперимент: выбор участников, скоростей, длины трассы, единиц.
2. **«Прогноз»** — серия из predictRounds задач, за каждую 0–3 звезды. ChallengeGenerator выдаёт задачи трёх видов
   (числа «красивые», ответы в пределах трассы):
   - **«Где он будет?»** — дано v и t, ученик перетаскивает флажок на трассе туда, где окажется участник через t секунд;
   - **«Когда финиширует?»** — дано s и v, ученик вводит или выставляет время;
   - **«Подбери скорость»** — дано: флажок на расстоянии s и время t; ученик ставит слайдером скорость так,
     чтобы участник оказался у флажка ровно в момент сигнала.

   После ответа — запуск заезда, проверка и разбор с формулой. Звёзды: ≤ 2 % ошибки — 3, ≤ 10 % — 2,
   ≤ 25 % — 1, иначе 0. В конце — итог «12 из 15 ★».
3. **«Средняя скорость»** — один участник, два участка с разной скоростью (граница отмечена на трассе).
   Перед стартом спросить: «Как думаешь, какой будет средняя скорость?» (ввод числа). После финиша показать
   v_ср по формуле, среднее арифметическое скоростей и почему они различаются (на медленном участке участник
   провёл больше времени). На графике s(t) — ломаная и пунктир средней скорости.

## События на сайт (`PhyslabPost`)

- `started` — после Init.
- `finished` `{ racer, kind, speed, time, distance }` — участник пересёк финиш.
- `challenge` `{ kind, given, expected, answer, stars }` — ответ в «Прогнозе».
- `challengeSummary` `{ rounds, stars, maxStars }` — итог серии.
- `paramsChanged` `{ key, value }` — с дебаунсом 300 мс.

## UI (UI Toolkit, на русском)

- Палитра сайта: `#01597B` (основной), `#5DB3C1`, `#99D8DE`, `#E2E8ED` (фон панелей), `#F2BA00` (акцент, звёзды).
  Цвета участников — `#01597B`, `#F2BA00`, `#E0525B`.
- Верх: вкладки режимов. Слева: свёртываемая панель параметров. Низ: график и шкала времени.
  Центр всегда свободен для трассы.
- От iframe 900×506 до полного экрана 1920×1080; на узкой ширине панель сворачивается в кнопку.
- Крупные элементы под тач: перетаскивание флажка, слайдеры не меньше 32 px по высоте.
- Кириллица обязательна (TMP — font asset с диапазоном 0400–04FF или динамический шрифт); числа — с десятичной
  запятой («37,5 м»).
- Контролы из `hiddenControls` скрыты, но их значения из конфига применяются.

## Производительность и WebGL

- 60 FPS на встроенной графике: без real-time теней, без постпроцессинга, атлас спрайтов/простые материалы,
  пул объектов для меток-«следов» (не Instantiate каждую секунду).
- Билд по возможности < 20 МБ, Managed Stripping — Medium.
- **Compression Format = Disabled** (или Brotli/Gzip + Decompression Fallback) — сервер сайта не отдаёт заголовки
  для .br/.gz.
- Не использовать System.Threading, файловую систему, `Application.OpenURL`.

## Сборка

- Пункт меню PhysLab → Build WebGL → Speed Race, выход `Builds/WebGL/speed-race/` (вне Assets).
- Полную сборку запусти один раз в конце.

## Проверка (Definition of Done)

1. Консоль без ошибок и предупреждений; все EditMode-тесты проходят.
2. Play Mode, скриншоты камеры:
   а) «Заезд»: пешеход и велосипедист на середине трассы — видны метки и график;
   б) финиш с пьедесталом и формулой;
   в) «Прогноз»: задача «Где он будет?» с флажком и разбором ответа;
   г) «Средняя скорость» после финиша: v_ср и среднее арифметическое рядом;
   д) режим км/ч.
   Сверь числа на табло и графике с ручным расчётом.
3. `SendMessage("ModuleRoot","Init","{\"mode\":\"average\",\"avgV2\":10}")` применяет параметры;
   `"{}"` даёт дефолты; мусорная строка не роняет симуляцию.
4. Перемотка шкалы времени вперёд и назад даёт те же положения, что и обычное воспроизведение.
5. Итоговый отчёт: дерево файлов, что добавлено в Core, упрощения, JSON конфига по умолчанию, список событий.

Работай поэтапно: разведка → модель и тесты → сцена и визуал → режимы → UI → проверка → сборка.
После каждого этапа коротко отчитывайся.
